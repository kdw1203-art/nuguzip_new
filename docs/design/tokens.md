# 디자인 시스템 한 장 (2026-08-25)

이번 라운드에서 시각화·모션·타입이 시스템으로 생겼다. 다음에 화면을 만드는
사람이 같은 규칙을 쓰라고 적어 둔다. **여기 없는 값을 새로 만들지 않는 것**이
이 문서의 목적이다.

## 1. 글자 — 램프 5단계만 쓴다

`text-[13.5px]` 같은 임의값은 쓰지 않는다. 2026-08-25 기준 앱 전역에서
2,248곳을 아래 5개로 수렴시켰다(워크벤치 한 화면에만 13종이 섞여 있었다).

| 클래스 | 크기 | 쓰는 자리 |
|---|---|---|
| `.t-display` | 24/28px · 800 | 화면 최상단 헤드라인 (페이지당 1개) |
| `.t-title` | 19/21px · 800 | 섹션 제목 |
| `.t-section` | 15px · 800 | 카드 제목 |
| `.t-body` | 13px | 본문 |
| `.t-sub` | 11px | 보조 설명 |
| `.t-caption` | 9px | 출처·기준시점·각주 |

숫자에는 `.t-num`(tabular-nums)을 함께 준다 — 자릿수가 바뀌어도 옆 요소가
밀리지 않는다.

## 2. 색 — 토큰만. raw hex 금지

`#1d4fd8` 을 클래스나 인라인 style 에 적지 않는다. `check:contrast-tokens`
게이트가 라이트·다크 44조합을 검사하는데, 그 보증은 **토큰을 쓸 때만** 유효하다.

- 계열: `primary`(단지 하나) · `success`(지역·시장) · `warning`(내 기록)
- 의미: `danger`(위험·상승) · `success`(안전·하락) · `text-3`(중립)
- 각각 `-soft` 배경 짝이 있다 (`bg-primary-soft text-primary`)
- 관리자 다크 셸은 `ai-accent` / `ai-text` / `ai-muted` / `ai-danger`

## 3. 그림 — `app/components/viz`

전부 서버 컴포넌트 · 순수 SVG(클라이언트 JS 0)다. 색은 `currentColor` 를
타므로 **부모에 계열 색 클래스**를 준다.

| 컴포넌트 | 언제 |
|---|---|
| `Spark` | 카드 안 작은 추세선 |
| `TrendChart` | 지수·시계열 본 그림 (격자·범위·끝점) |
| `Bars` | 건수·물량 (최댓값만 진하게) |
| `Gauge` | 0~100 척도 (중립선 필수) |
| `RankBars` | 순위 — 길이로 먼저 읽힌다 |
| `Radar` | 비교 (최대 3개) |
| `Donut` | 비율 하나 |

기하 계산은 `lib/viz/geometry.ts`(순수 함수)에 있고 테스트로 잠겨 있다.

**정직성 규칙**: 유한한 값이 2개 미만이면 `null` 을 낸다 — 아무것도 그리지
않는다. 한 점짜리 선이나 평평한 가짜 선은 "데이터가 있다"는 거짓 신호다.

## 4. 움직임

| 클래스 | 무엇 |
|---|---|
| `.tile` | 카드 상호작용 전부 (들림·그림자·테두리·아이콘·화살표·눌림·포커스) |
| `data-reveal=""` | 스크롤 진입 등장 (속성 하나 — 서버 컴포넌트에서도 됨) |
| `.rank-fill` | 막대 성장 |
| `.gauge-arc` | 게이지 호 그리기 |
| `.sk` | 스켈레톤 |
| `.run-steps` | 진행 단계 |
| `.pulse-dot` | 갱신 중 표시 |

`.card-hover` 는 `.tile` 로 흡수됐다(별칭만 남음). 새로 쓰지 않는다.

**두 가지 규칙**
- 호버는 `(hover: hover) and (pointer: fine)` 안에서만. 터치에서 첫 탭이
  호버로 먹혀 두 번 눌러야 하는 문제를 막는다. 누름(`:active`)은 터치에도 남긴다.
- 모든 애니메이션은 `prefers-reduced-motion: reduce` 에서 꺼진다.

## 5. 숫자를 적을 때의 규칙 (이게 이 제품의 핵심이다)

1. **기준시점과 출처를 반드시 함께 적는다.** 없으면 그 숫자는 근거를 잃는다.
2. **"데이터 없음"과 "조회 실패"를 끝까지 다르게 말한다.** 실패를 빈칸으로
   내보내면 사용자는 표본이 없는 것으로 읽는다.
3. **공표 지연을 설명한다.** `publishedAsOfLabel()` — "2026.07 공표분 ·
   공표 주기상 최신"과 "3개월 지연"은 다른 사실이다.
4. **표본 수를 적는다.** 3건 평균과 300건 평균은 같은 굵기로 쓰면 안 된다.
5. **추정과 실측을 배지로 가른다.**
6. **없는 모델의 결과를 그리지 않는다.** `/analysis/cycle` 에 전망 곡선이
   없는 이유가 그것이다.

## 타입 램프 게이트 (`npm run check:type-ramp`)

색은 `check:contrast-tokens` 가 잡는데 **크기는 아무도 안 보고 있었다.**
그 사이 `/notifications` 한 화면 안에서 12 / 10.5 / 10 세 크기가 섞여, 한 칸도
안 되는 차이로 제목·본문·메타가 붙어 버렸다(무엇이 제목인지 안 보였다).

허용 크기는 램프 그대로다 — **9 · 11 · 13 · 15 · 19 · 21 · 24 · 28 px**.
TSX 의 `text-[10px]`·`text-xs`(12)·`text-sm`(14) 과 CSS 의 `font-size: 12px`
를 모두 본다(주석은 제외). 공용 클래스가 CSS 에 숨어 있어 화면 여러 개가
한꺼번에 램프를 벗어나 있던 적이 있어 CSS 도 함께 본다.

한 번에 다 못 고치므로 **래칫**이다: 파일별 이탈 수를 `scripts/type-ramp-baseline.json`
에 적어 두고 **늘어나면 실패**한다. 줄이면 `npm run check:type-ramp -- --write`
로 baseline 을 내린다. 새 코드는 램프를 지키게 강제되고, 기존 빚은 화면 단위로
갚는다.

| 명령 | 하는 일 |
| --- | --- |
| `npm run check:type-ramp` | 게이트(빌드 체인에 포함) |
| `npm run check:type-ramp -- --report` | 파일별 현황 상위 30 |
| `npm run check:type-ramp -- --write` | baseline 갱신(내려가기만) |

### 카드 한 장의 표준 배치

목록 카드는 **제목 13 · 본문 11 · 메타 9** 세 칸을 쓴다. 좌측 아이콘 배지는
제목 첫 줄(13×1.6≈21px)의 세로 중앙에 맞춘다 — 배지 높이(34)와 줄 높이가
달라 `items-start` 로 두면 배지가 6px 떠 보인다. 안 읽음 점도 같은 줄 중앙이다.
스켈레톤은 실제 카드 실측 높이와 같아야 한다(다르면 데이터가 붙는 순간 밀린다).
