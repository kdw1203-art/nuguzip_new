# soft-404 정책 — 동적 페이지의 미존재 id 가 HTTP 200 인 이유

기록일 2026-08-15 · 상태: **수용(accepted)** — 완화책으로 관리, 상태코드 404 전환은 하지 않음

## 실측

미존재 id 로 접근하면 모든 동적 상세 페이지가 **HTTP 200 + "찾을 수 없음" 본문**을 돌려준다.

| 경로 | 일반 UA | Googlebot UA | Yeti(네이버) UA | 본문 noindex |
|---|---|---|---|---|
| /notes/{없는 uuid} | 200 | 200 | 200 | ✓ |
| /complex/{없는 id} | 200 | — | — | ✓ |
| /town/news/{없는 id} | 200 | — | — | ✓ |
| /reports/209901 | 200 | — | — | ✓ |
| /town/experts/{없는 uuid} | 200 | 200 | — | ✓ |

(2026-08-15 프로덕션 curl 실측. `notFound()` 는 정상 호출되고 UI 도 not-found 로 바뀐다 — 상태코드만 200 이다.)

## 왜 이렇게 되는가 (메커니즘)

Next.js App Router 의 **스트리밍** 때문이다. 부모 세그먼트에 `loading.tsx` 가 있으면
(예: `app/town/loading.tsx` 가 `/town/experts/[id]` 를 덮는다) 서버는 셸+로딩 폴백을
**즉시 200 으로 흘려보내고**, 페이지 본문은 Suspense 안에서 뒤이어 스트리밍된다.
`notFound()` 가 그 뒤에 던져지면 이미 전송된 상태코드는 바꿀 수 없고, Next 는
not-found UI 를 스트림에 실어 보낼 뿐이다.

`generateMetadata` 에서 `notFound()` 를 던져도 같다 — Next 15.2+ 의 스트리밍
메타데이터는 일반 UA 에서 메타데이터 해석을 첫 플러시와 분리하며, Googlebot 은
JS/스트림 처리가 가능한 봇이라 블로킹 목록(htmlLimitedBots)에 들어 있지 않다.
(전문가 상세에서 실제로 시도했고, 실측 결과 여전히 200 이었다 — 0e1dd2d.)

## 진짜 404 로 바꾸려면 무엇을 포기해야 하나

첫 플러시 **이전**에 존재 판정이 끝나야 한다. 선택지는 전부 비용이 크다:

1. **`loading.tsx` 경계 제거** — 해당 트리 전체의 스켈레톤 UX 를 잃고, 모든
   내비게이션이 DB 조회를 기다린 뒤에야 화면이 바뀐다(체감 성능 회귀).
2. **미들웨어에서 존재 확인** — 엣지 미들웨어가 요청마다 DB 를 조회해야 한다.
   지연 추가 + 존재 판정 로직 이원화(페이지와 미들웨어 양쪽 유지).
3. **동적 상세를 전부 SSG/ISR 로** — `force-dynamic` 이 필요한 개인화·실시간
   요건(소유자 분기 등)과 충돌한다.

## 왜 수용해도 되는가 (완화 스택)

1. **모든 not-found 분기가 `noindex` 메타를 내보낸다** — 위 표에서 전 라우트 실측 확인.
   구글·네이버는 noindex 를 읽으면 그 URL 을 색인하지 않는다.
2. **본문이 정직하다** — "찾을 수 없어요"를 말하지, 가짜 콘텐츠를 그리지 않는다.
   검색엔진의 soft-404 분류기는 이런 페이지를 오류 페이지로 취급한다(구글 공식 문서).
3. **사이트맵 위생** — 사이트맵·RSS 에는 실존 URL 만 실린다(빌드 게이트로 강제).
   크롤러가 쓰레기 URL 을 만날 경로 자체가 내부에는 없다.

## 규칙 (새 동적 상세 페이지를 만들 때)

- 미존재/비공개 분기는 반드시 `robots: { index: false }` 메타를 내보낸다.
  (`generateMetadata` 의 실패 분기 — 이 저장소의 기존 패턴을 따라라.)
- not-found 본문은 "찾을 수 없음"을 명시하고, 가짜 데이터로 채우지 않는다.
- 사이트맵에 넣는 URL 은 존재가 확인된 것만 (기존 게이트 유지).
- 상태코드 200 을 "고치려" `loading.tsx` 를 지우지 마라 — 위 트레이드오프를 읽고
  정말 필요하면 이 문서를 갱신하고 결정을 뒤집어라.
