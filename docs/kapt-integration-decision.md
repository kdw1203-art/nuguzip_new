# [#138] 관리비 공시(K-apt) 연동 판정 — 2026-08-23

## 결론
**조건부 도입 (오너 활용신청 후 개발 착수).** 무료·공식 API가 존재하고, 키는
이미 파이프에 있는 `DATA_GO_KR_SERVICE_KEY`(청약홈·온비드에서 사용 중) 계정을
재사용할 수 있다 — 추가 비용 0원. 다만 해당 API에 대한 **활용신청**(포털에서
버튼 1회)과 kaptCode↔우리 단지 매핑 작업이 선행돼야 한다.

## 조사 결과 (2026-08-23 웹 실측)
K-apt(공동주택관리정보시스템, 한국부동산원 운영)의 데이터는 공공데이터포털에
다음 형태로 공개돼 있다:

1. **공동주택 단지 관리비 정보** (data.go.kr 데이터셋 3039714, 오픈API 제공)
   — 단지별 월 관리비. 공용관리비(인건비·청소비·경비비·수선유지비 등)와
   개별사용료(난방·급탕·전기·수도) 항목 구조. 세부 필드 목록은 포털 로그인
   후 활용신청 화면에서 최종 확인 필요(포털이 비로그인 크롤을 막아 이 문서
   시점에는 데이터셋 존재·구성 개요까지만 확인함).
2. **공동주택 단지 목록제공 서비스** (15057332, 오픈API) — kaptCode 발급 원천.
3. **공동주택 기본 정보제공 서비스** (15058453, 오픈API) — 세대수·승인일 등.
   ※ CODEF 명세(docs/codef-integration.md)의 "단지 기본정보(K-apt)"와 동일
   원천이다. 공공데이터포털 직접 호출이면 CODEF 유료 경유가 필요 없다.

## 가치 판단 (왜 하는가)
- 단지 페이지 체류 자산: 실거래·전월세·시세 다음으로 많이 찾는 숫자가
  "관리비 얼마 나와요?"다. 임장노트 체크리스트에도 관리비 항목이 이미 있다.
- 경쟁 표면: 네이버부동산도 K-apt 관리비를 노출한다 — 없으면 비교에서 빠진다.
- 우리 단지 2.6만 페이지에 "월 관리비 평균 ㎡당 N원" 한 줄만 붙어도
  검색 스니펫 차별화("관리비" 롱테일 유입)가 된다.

## 비용·리스크
- 금전 비용 0 (공공 무료 API). 개발 비용은 매핑이 대부분:
  kaptCode 는 K-apt 고유 체계라 우리 complex(국토부 실거래 명칭 기반)와
  이름 매칭이 필요하다 — 뉴스 단지 링크(#117)에서 겪는 별칭 문제가 재등장.
  단지 목록 API의 주소(법정동)를 조인 키로 쓰면 정확도를 올릴 수 있다.
- 호출량: 의무공개 단지 약 1.8만 — 월 1회 전체 갱신이면 무리 없는 규모.
  (관리비는 월 단위 공시라 일 단위 크론이 필요 없다.)

## 실행 계획 (활용신청 회신 후 1회차)
1. `lib/kapt/client.ts` — odcloud/공공데이터 패턴 재사용(applyhome 클라이언트와 동일 구조).
2. kaptCode 매핑 테이블(`kapt_complex_map`) — 법정동+단지명 매칭, 미매칭은 관리자 큐.
3. `complex_mgmt_fees` 월 적재 크론 + 단지 페이지 "관리비" 섹션(㎡당 환산 포함).
4. 출처 표기: "K-apt 공동주택관리정보시스템 · 한국부동산원" (공공데이터 이용조건 명시).

## 👤 오너 액션 (5분)
data.go.kr 로그인(기존 청약홈 키 계정) → 위 3개 API "활용신청" → 승인 문자
오면 번호(#138)로 회신. 키 재발급은 불필요 — 기존 키로 호출된다.
