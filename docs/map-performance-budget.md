# 지도 성능 예산 (#77) — 현행 상한 인벤토리와 계측 계획

2026-08-23 · 시각 QA 회차 산출물. 결론: **렌더 상한·뷰포트 로드·디바운스는 이미 코드에
존재한다. 남은 것은 "숫자가 예산 안인지"의 실측이며, 그 계측기는 #91 Lighthouse 주간
CI(월요일, /map 포함)와 기존 RUM(/api/vitals)이다. 실측 수치가 예산을 넘기 전까지
추가 조정은 하지 않는다** — 측정 없는 튜닝은 회귀만 만든다.

## 현행 상한 (app/map/map-client.tsx 실측 인벤토리)

| 레이어 | 로드 방식 | 상한 |
|---|---|---|
| 단지 클러스터(낮은 줌) | 서버 그리드 집계 | 셀 단위 — 마커 수 = 셀 수 |
| 단지 포인트(높은 줌) | 뷰포트 재조회 | 거래량 상위 300 (화면에 안내 문구) |
| 매물 | 토글 + 뷰포트(idle) | 서버 쿼리 상한 |
| 정비사업 | 토글 + bbox(idle, 500ms 디바운스) | 2,000 |
| 입주 예정(#74) | 토글 시 1회 | 1,500 (일 단위 데이터라 재조회 없음) |
| 지역 시세 | 시·군·구 줌에서만 | 62 |

이벤트: idle 기반 재조회(이동 중 미발화) + 500ms 타이머 디바운스 + AbortController
취소가 정비사업·매물 경로에 적용돼 있다.

## 예산 (넘으면 조정을 시작하는 선)

- Lab(#91 주간 CI, /map): LCP ≤ 4.0s · CLS ≤ 0.1 · TBT ≤ 600ms — lighthouse-budget.json
- 화면 내 동시 마커 ≤ 500 (현행 구성상 클러스터 줌에서 구조적으로 만족)
- 이동(팬) 중 네트워크 요청 0건 (idle 재조회 원칙 위반 여부는 코드리뷰로 감시)

## 조정 트리거와 예정 수단 (측정이 예산을 넘겼을 때만)

1. TBT 초과 → 마커 DOM 대신 캔버스 오버레이 검토, 정비사업 상한 2,000→800 하향
2. CLS 초과 → 8/16 배포분(CLS 0.825 수리)의 재검증 — 상단 패널 예약 높이 확인
3. 팬 중 프레임 드랍(RUM INP) → idle 디바운스 500→800ms, 마커 라벨 지연 렌더

## 왜 이 환경에서 실측하지 않았나

이 작업 컨테이너는 브라우저의 외부(HTTPS) 접속이 프록시에서 차단되고(curl 만 허용,
실측 ERR_CONNECTION_RESET), 로컬 기동은 네이버 지도 키가 없어 지도 캔버스가 뜨지
않는다 — 즉 여기서 만든 수치는 실사용과 무관하다. 대신 GitHub Actions 러너(제약
없음)에서 도는 #91 워크플로가 매주 같은 예산으로 /map 을 잰다. 첫 수치는 다음 월요일
실행(또는 Actions 탭 수동 실행)에서 나온다.
