# 이미지 전략 결정 (#93) — 실측 기반

2026-08-23 · 조사 회차 산출물. 결정: **next/image 를 노트 커버부터 단계 도입(시각 QA 회차에서 전환), 변환 CDN 도입은 보류, 업로드단은 현행 유지.**

## 현재 상태 (실측)

- 업로드단: 클라이언트 리사이즈 이미 있음 — `lib/client/image-resize.ts`, 최대 1600px, jpeg/png/webp 유지. 원본 그대로 올라가는 경로 없음.
- 표시단: `next/image` 미사용. 커스텀 `<img>`(CoverImage 등) + `loading="lazy"` 는 주요 목록에 적용돼 있음. `srcset` 없음 — 모바일도 1600px 원본을 받는다.
- 프로덕션 실측 (2026-08-23, /town 첫 화면):
  - HTML 141.8KB
  - 노트/랩 카드 PNG 표본 3건: 115KB · 127KB · 203KB (평균 ≈ 148KB)
  - 그리드 12장 노출 가정 시 이미지 전송 ≈ 1.8MB/뷰 — 모바일에서 지배적 비용.
- `next.config.ts` 의 `images.remotePatterns` 는 이미 우리 Supabase 호스트로 잠겨 구성돼 있음 (오픈 프록시 방지 주석 포함) — **도입 인프라는 준비 끝, 표시단 전환만 남은 상태.**

## 선택지 비교

| 선택지 | 전송량 | 비용 | 리스크 |
|---|---|---|---|
| ① 현행 유지 | 1600px 원본 그대로 (~148KB/장) | 0 | LCP·데이터 요금 손해 지속 |
| ② next/image 도입 | AVIF/WebP + srcset — 모바일 표본 기준 60~75% 절감 예상 (PNG→AVIF 전환률 실측치 범위) | Vercel 이미지 최적화 쿼터 (현 트래픽 일 ~수백 뷰 규모에서는 무료 한도 내) | 레이아웃 시프트·잘림 등 시각 회귀 — 화면 검수 필요 |
| ③ 변환 CDN (Cloudflare Images 등) | ②와 유사 | 월 고정비 + 도메인/캐시 구성 | 지금 트래픽에선 과투자 |

## 결정과 근거

1. **②를 채택하되 전환은 #73/#77/#89 와 같은 시각 QA 회차에서 실행한다.**
   이미지 컴포넌트 전환은 fill/sizes 지정에 따라 카드 레이아웃이 눈에 띄게 변할 수
   있어, 스크린샷 검수 없이 일괄 전환하면 안 된다(다크모드 회차와 같은 이유).
   전환 순서: TownFeed 카드 커버 → 노트 상세 캐러셀 → 뉴스 썸네일.
   `sizes` 기준: 그리드 카드 `(max-width: 768px) 50vw, 25vw`.
2. **③ 변환 CDN 은 보류.** 월 수천 뷰 규모에서 고정비를 정당화할 전송량이 아니다.
   Vercel 무료 한도 초과가 관측되면(관리자 트래픽 화면) 그때 재평가.
3. **업로드단은 손대지 않는다.** 1600px 상한 리사이즈가 이미 있고, 원본 보존 요구
   (인쇄·리포트 판매)와의 균형점으로 적절하다.
