### 1. GitHub 개인 액세스 토큰이 작업 트리에 평문으로 있다 `[소유자]` · S
**근거** `.git/config:10` 의 remote URL 이 `https://x-access-token:ghp_…@github.com/…` 형태다.
**문제** 이 토큰은 저장소 push 권한을 가진다. push 권한은 곧 `deploy.yml` 수정 권한이고,
그 워크플로는 Supabase service role key 를 환경에 갖고 있다. 즉 이 토큰 하나로 DB 전체가 열린다.
**gitleaks 는 이걸 못 잡는다** — 추적 파일과 커밋 히스토리만 스캔하는데 `.git/config` 는 둘 다 아니다.
(`git log -S` 로 커밋된 적 없음을 확인했다.)
**조치** GitHub Settings → Developer settings → Tokens 에서 **해당 토큰 즉시 폐기**.
이후 SSH 또는 credential helper 로 재설정. URL 에 토큰을 박는 방식은 쓰지 않는다.
**효과** 현재 열려 있는 유일한 "전체 장악" 경로가 닫힌다.

### 2. service role key 가 핀 고정 안 된 서드파티 액션에 노출된다 · S

**문제** 그 태그가 언젠가 다른 커밋을 가리키면, 액션이 `process.env` 에서 service role key 를 읽는다.

**효과** 공급망 경로 차단. 30분 작업.

### 3. Supabase 클라이언트에 전체 예산이 없다 — 802회 타임아웃의 뿌리 · S
**근거** `lib/supabase/service.ts:33`

`totalBudgetMs` 를 넘기지 않아 `resilient-fetch.ts:75` 에서 0("상한 없음")이 된다.

**조치** `makeResilientFetch({ timeoutMs: serviceReadTimeoutMs(), totalBudgetMs: 30_000 })`
**효과** 이 한 줄이 이번 감사 전체에서 **단일 최대 레버리지**다.
`getComplexById` · `getTransactionHistory` · `searchComplexes` · `getAllRegionSnapshots` ·

## 감사에서 "문제 아님" 으로 확인된 것 (재보고 방지)

- **`get_automation_script` 는 인증 우회가 아니다.** 비교가 상수 시간은 아니지만 비밀값이 48자리 hex(≈192비트)라
  바이트 단위 타이밍 차이는 나노초, PostgREST 네트워크 지터는 밀리초다. 측정 불가능하고 무차별 대입도 불가능하다.
  다만 회전·레이트리밋이 없는 단일 공유 비밀이고, `ingest_daily_news` 는 `is_published = true` 로 삽입하므로
  **비밀이 새면** 임의 콘텐츠가 검수 없이 게시된다. `revoke execute … from anon` 은 해 두는 편이 좋다.
- **자격증명 테이블의 `rls_enabled_no_policy` 65건은 대부분 오경보다.** `password_reset_tokens`,
  `automation_secrets`, `toss_login_tokens`, `iap_receipts`, `payment_audit_logs`, `app_users`, `user_consents` 는
  anon·authenticated 권한이 **아예 회수돼 있어** PostgREST 가 도달할 수 없다. 방어선 두 겹이 다 닫혀 있다.
  다만 `web_vitals` · `push_subscriptions` · `geo_backlog_tmp` · `news_articles` 4개는 anon INSERT 권한이 살아 있다
  (RLS 가 막고 있어 오늘은 안전하지만, 훗날 관대한 정책 하나면 열린다). `revoke insert … from anon` 권장.
- **`is_admin_request` 는 오경보다.** `auth.email()` 은 검증된 Supabase JWT 에서 온다. 클라이언트 헤더가 아니다.
  `auth.ts:236-293` 도 `token.role` 을 DB 프로필과 env 허용목록에서만 설정한다. **관리자 판정은 건전하다.**
  `app/api/admin/**` 전부 role 검사, `app/api/cron/**` 13개 전부 `CRON_SECRET` 검사를 한다.
- **이미지 alt · 스킵 링크 · 랜드마크 · 세이프에어리어 · ARIA 시맨틱**은 전부 정상이다.
  `<div onClick>` 은 저장소 전체에 1건뿐이고 그것도 무해한 광고 클릭 추적 래퍼다.
- **`auth_rls_initplan` 0건, `duplicate_index` 0건** — RLS 정책 성능은 이미 잘 돼 있다.
- **cron 배치 로직 자체는 건전하다** — `apt-detail-enrich` 는 `limit ≤ 200` + `mapWithConcurrency`. 무한 루프 없다.
