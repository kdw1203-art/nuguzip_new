# 누구집 운영 체계 정본 (Operating System) — v1 · 2026-08-17

> 이 문서는 "사람의 기억"을 대체하는 운영 정본이다. 새 AI 세션은 작업 전에
> 이 문서를 읽고 같은 프로세스로 움직인다. 갱신은 이 파일을 직접 고친다.

## 0. 설계 원칙 — 사람은 병목이 아니라 승인자다

역할은 셋뿐이다.

| 역할 | 정의 | 맡는 것 |
|---|---|---|
| **SYSTEM** | CI 게이트·크론·트리거 등 무인 자동 장치 | 검증·수집·경보·정기 보고 |
| **AGENT** | AI 세션(Claude) — 지시 또는 예약으로 기동 | 구현·조사·수리·문서·준비물 제작 |
| **OWNER** | 대표(고대웅) | 자격증명·계약·결제·법적 서명 **만** |

격상 규칙: OWNER 에게 가는 일은 "계정 소유자만 법적으로 할 수 있는 일"로
한정한다. 그 외 전부는 AGENT 가 준비물을 복사-실행 수준까지 만들어 넘긴다.
(실측 교훈: 2026-08 토스 회신 — 회신문·PPT·테스트계정 인증까지 AGENT 준비
후 OWNER 는 비밀번호 기재와 발송만.)

## P1. 배포 파이프라인 — 담당 SYSTEM (AGENT 는 호출자)

**순서**: 코드 수정 → `tsc` → 게이트 9종 → 유닛 → `next build` → 커밋(트레일러
규격) → push → GH Actions(게이트 재실행·빌드·Vercel 배포·배포 후 스모크) →
READY → 프로덕션 콘텐츠 신호 확인.

**체크리스트 (AGENT, push 전)**
- [ ] `npx tsc --noEmit` 통과
- [ ] `scripts/check-*.mjs` 전부 exit 0 (파이프 금지 — 직접 실행, 8/15 교훈)
- [ ] `npm test` 통과 (글롭은 `tests/unit/*.test.ts` — .mjs 는 안 잡힘)
- [ ] UI 변경 시 P5 표준 QA 스크린샷
- [ ] 커밋 메시지에 왜/실측 근거, Co-Authored-By + Claude-Session 트레일러

**품질 기준**: 게이트 exit 0 전원 + First Load JS 라우트 예산 250kB 경고 없음
+ 배포 후 프로덕션에서 변경 콘텐츠 신호(grep) 확인.

**보고**: 커밋 메시지가 곧 보고서다(수치·실측 포함). 배포 실패 시에만 대화 보고.

**알려진 장애 모드**: ① GH Actions 대기열 지연(최대 20분+, 8/16-17 실측) —
23분 무배포면 빈 커밋 재점화 1회, 그래도 없으면 GitHub 장애로 보고 대기.
② PAT 에 workflow 스코프 없음 — `.github/workflows/*` 수정 푸시 불가(OWNER 항목).

## P2. DB 변경 — 담당 AGENT (원장 미러 규율)

**순서**: `apply_migration`(MCP) → 원장에서 base64+md5 재조회 → 바이트 동일
미러 파일 `supabase/migrations/<version>_<name>.sql` → `check-migration-ledger` PASS → P1.

**체크리스트**
- [ ] DDL 은 반드시 apply_migration (execute_sql 로 DDL 금지)
- [ ] 미러 md5 = 원장 md5 (파이썬 검증 후 기록)
- [ ] 새 테이블: RLS on + 필요한 최소 정책만 (service 전용이면 정책 0)
- [ ] 성장 상한 설계 (예: region_demand_requests 의 (norm, day) 유니크)

**품질 기준**: ledger PASS · advisors ERROR/WARN 0 유지 · "unused index 163건"
류 INFO 는 사용자 규모 감안해 삭제하지 않는다(성장 전 지표 부족).

**보고**: 커밋 메시지 + 주간 브리핑의 DB 항목.

## P3. 운영 헬스·경보 — 담당 SYSTEM

**가동 중**: ETL·크론 25종(GH Actions 06:00 UTC) · critical 경보(etl_freshness
+ error 감시, #374) · Vercel 크론(소셜 02:00/02:20 UTC, 빌링은 개방 시).

**품질 기준**: 런타임 에러 24h 0건대 유지 · ETL 신선도 라벨 최신 · 크론 산출물
테이블(social_uploads 등)에 "예상 산출물 존재".

**자동화 다음 단계**: 산출물 하트비트 — "크론이 돌았다"가 아니라 "산출물이
생겼다"를 감시(소셜 첫 실가동 검증 후 소셜도 편입).

**보고**: 경보는 인박스/로그 → AGENT 가 다음 세션에서 원인 수리. 무소식이 정상.

## P4. 주간 지표 브리핑 — 담당 SYSTEM→AGENT (가동 중)

- **일정**: 매주 월 09:00 KST (trigger `trig_01QyTfLR8NMqMfq93bX2Mih7`)
- **내용**: 가입·노트·방문·퍼널·커버 수요·결제·소셜·리포트/전문가, 지난주 vs 전주
- **품질 기준**: 사실 우선 — 조회 실패는 "실패"로 표기, 수치 창작 금지.
  병목 5 프레임(①결제 ②유통 ③관리 스프린트 ④기능 동결 ⑤커버 수요)로 권장 행동 1~2개
- **보고**: 푸시 알림 + 대화. OWNER 는 읽고 관리 스프린트 안건으로 넘긴다.

## P5. UI 검증 QA — 담당 AGENT (표준 스크립트)

**순서**: 로컬 프로덕션 서버(`AUTH_SECRET` 더미 필수 — 없으면 로컬 500) →
`node scripts/qa-shots.mjs [routes...]` → 1280/390 스크린샷 육안 확인 → P1.

**체크리스트**: 쿠키 동의·베타 모달 시드 자동 처리됨 · 데이터 없는 로컬에선
"빈 상태의 정직성"을 검증(실패≠없음 문구) · 클라이언트 전용 UI 는 라우트
목킹으로 증명(예: 자기회복, 무결과 행).

**품질 기준**: 잘림·겹침·오버플로 0 · 스켈레톤→콘텐츠 높이 동일(CLS) ·
다크 딤 위 시트는 불투명.

  - [ ] 완료 항목은 AGENT 에게 한 줄 통보("~했어") → 문서·후속 자동 반영
- **품질 기준**: owner-todo 항목 체류 14일 초과 0건이 목표
- **보고**: 없음 — 완료 통보가 곧 보고

## P7. 외부 심사·사실 잠금 — 담당 AGENT+SYSTEM

**패턴**(토스에서 확립): 회신문 초안은 **사이트 실측 전수 대조** 후 작성 →
제출 사실은 `check-toss-review-freeze` 게이트로 잠금(사실이 바뀌면 빌드 실패)
→ 표기 잔재는 발견 즉시 정정 배포(예: 메타 제목 '법무').

**품질 기준**: 회신문 주장과 사이트가 한 글자도 어긋나지 않는다.

## 자동화 로드맵 (사람 의존 추가 제거)

1. 소셜 산출물 하트비트를 P3 경보에 편입 (첫 실가동 검증 직후)
2. RESEND 개통 시: 주간 브리핑을 이메일로도 (OWNER 키 등록이 선행)
3. 커버 수요 임계 경보 — 같은 지역 수요 N건 도달 시 확장 후보 자동 통보
4. GH Actions 정체 자동 재점화 — 배포 무생성 20분 감지 시 빈 커밋 (현재는 수동 1회)
