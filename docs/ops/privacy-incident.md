# SOP — 개인정보 사고 대응 (v1, 2026-08-17)

> 유출·오노출 사고는 "빨리 아는 것"과 "기록하며 움직이는 것"이 전부다.
> 이 문서는 초안이며 법률 자문이 아니다 — ⚠️ 신고 기한·통지 요건은 개인정보
> 보호법과 시행령 기준으로 **법률 전문가 확인 후 확정**할 것.

## 우리가 다루는 개인정보 (최소 지도)

- 계정: 이메일, 소셜 로그인 식별자 (Supabase auth)
- 활동: 임장노트(비공개 포함), 좌표·사진, 문의 내용
- 거래: 포인트·구매 내역 (카드번호는 저장하지 않음 — 토스가 보관)
- 수집기: 페이지뷰(동의 기반, 무작위 키 — 계정 비연결)

## 사고 유형별 첫 30분

| 유형 | 즉시 행동 |
|---|---|
| 키 노출 (서비스 롤 키 등) | 해당 키 **즉시 재발급·교체**(Supabase/Vercel env) → 이전 키 폐기 확인 |
| 공개 화면에 개인정보 오노출 | 해당 화면 즉시 수정 배포(또는 라우트 차단) → 캐시 무효화 |
| DB 부정 접근 의심 | RLS·접근 로그 확인, 의심 세션 무효화, 비밀번호/키 일괄 교체 |
| 계정 탈취 신고 | 해당 계정 세션 무효화 + 본인 확인 후 복구 |

## 이후 24–72시간

1. **영향 범위 산정**: 어떤 데이터가, 몇 명이, 언제부터 — 추정이 아니라 로그로.
2. **기록**: 타임라인 문서 생성 (발견 시각·조치·근거) — 이 문서가 신고·통지의 원천.
3. **신고·통지 판단**: 유출 확인 시 보호위원회 신고 및 정보주체 통지 의무 검토
   (⚠️ 기한·요건·규모 기준은 전문가 확인 — 임의로 "괜찮겠지" 판단 금지).
4. **재발 방지**: 원인 계층(코드/설정/절차)별 수리 + 게이트 추가.

## 연락 체계

- 1선: AGENT 세션(탐지·수리·기록) → 즉시 OWNER 통지 (푸시+메일)
- 대외 창구: privacy 메일(nuguzip@naver.com) — 응답은 OWNER 승인 후 발송
