# 홈페이지 고도화 50 — 2026-08-02 실측 분석

전제: 2026-08-01 감사 50항목(사실 우선·신뢰성)은 46/50 완료·배포됐다. 이 문서는
그 위에서의 **고도화** — 사용성·전환·콘텐츠 깊이·성능 체감 — 를 다룬다.
각 항목은 현 코드/프로덕션 관찰에 근거하며, 근거 없는 항목은 넣지 않았다.
난이도: S(≤1시간) · M(반나절) · L(하루+). W1~W4 = 권장 실행 웨이브.

## A. 체감 성능·로딩 경험

1. **[W1·S] 무거운 동적 4라우트에 스켈레톤이 없다** — `/complex/[id]`,
   `/region/[id]`, `/map`, `/tx/[region]` 에 loading.tsx 부재(확인). DB 곁다리
   조회 8초 예산 동안 흰 화면. 스켈레톤이면 체감 대기가 절반으로 줄어든다.
2. **[W1·S] 단지 상세 이동이 풀 내비게이션** — 목록→상세에 프리페치 힌트가
   있는지 점검하고 Link prefetch 기본 유지 + 상세 첫 화면(개요 카드)을 곁다리
   조회와 분리해 먼저 그린다(현재 Promise.all 5건 완료 후 일괄 렌더).
3. **[W2·M] /map 초기 페이로드** — danji 30개 SSR + 클라이언트 재조회 이중.
   공유 캐시 도입(완)에 이어, SSR 목록을 24h 캐시 태그로 온디맨드 무효화.
4. **[W2·S] 이미지 lazy 정책 점검** — 커뮤니티 첨부·노트 사진에 loading=lazy,
   sizes 명시 여부 일괄 점검(없는 곳 실측 후 부여).
5. **[W3·M] 폰트 서브셋** — 한글 웹폰트 전체 로드 여부 확인, 서브셋/우선순위
   조정으로 LCP 개선.
