# 내집나우 SEO·GEO 반복 루틴

> N19(AI 인용 모니터링) · N24(GSC 쿼리 갭)의 실행 문서.
> 스케줄과 기록 양식은 자동화돼 있고, **관측은 사람이 한다**. 그 경계를 흐리지 않는 것이
> 이 문서의 핵심이다 — 자동으로 채워진 척하는 기록은 없는 기록보다 나쁘다.

일정은 `.github/workflows/seo-routines.yml` 이 잡는다. 시각이 되면 워크플로가 GitHub 이슈를
하나 열고, 그 이슈 본문에 이번 회차의 체크리스트가 들어 있다. 사람이 체크하고 결과를 이 문서
하단의 기록표에 붙인 뒤 이슈를 닫는다.

## N19 — AI 인용 모니터링 (격주, 매월 1일·15일 09:00 KST)

### 왜 하는가

GEO 의 성과는 순위가 아니라 **인용**이다. "내집나우가 검색에 잘 나오나"는 서치콘솔이 답해 주지만
"ChatGPT 가 서울 아파트 시세를 물었을 때 내집나우를 근거로 대는가"는 어떤 도구도 알려 주지 않는다.
직접 물어보고 적는 수밖에 없다. 격주 12회면 반년치 추세가 되고, 그때부터는 "인용이 늘고 있다"를
감이 아니라 기록으로 말할 수 있다.

### 고정 질의 10개

질의는 **바꾸지 않는다**. 바꾸는 순간 시계열이 끊기고, 비교 가능한 것은 같은 질문에 대한 답뿐이다.
새로 보고 싶은 질의가 생기면 아래 목록에 **추가**하되 기존 10개는 그대로 둔다.

| # | 질의 | 우리 쪽 대응 페이지 |
|---|---|---|
| Q1 | 서울 강남구 아파트 시세 알려줘 | `/region/gangnam` |
| Q2 | 송파구 아파트 실거래가 최근 추이 | `/region/songpa` · `/tx/송파구` |
| Q3 | 서울 아파트 매매 거래량 늘고 있어? | `/analysis/temperature` |
| Q4 | 전세가율이 뭐야 | `/glossary/전세가율` |
| Q5 | 임장 갈 때 뭘 봐야 해? | `/notes` · `/guide` |
| Q6 | 서울 재개발 진행 단계 정리해줘 | `/redevelopment` |
| Q7 | 이번 달 서울 부동산 시장 요약 | `/reports/<이번 달 ym>` |
| Q8 | 아파트 단지끼리 실거래가 비교할 수 있는 곳 | `/complex/compare` · `/complex/pair` |
| Q9 | 서울 아파트 입주 물량 얼마나 돼? | `/supply` |
| Q10 | 부동산 실거래가 데이터 API 있어? | `/developers` |

### 관측 절차 (회차당 15~20분)

각 질의를 **ChatGPT(웹검색 켠 상태) · Claude · Perplexity · 네이버 큐** 네 곳에 그대로 넣고,
답변에서 다음 세 가지만 본다.

1. **인용(C)** — 답변에 naezipnow.com 링크나 "내집나우" 출처 표기가 있다.
2. **언급(M)** — 출처는 아니지만 본문에 내집나우가 이름으로 나온다.
3. **없음(–)** — 둘 다 아니다.

숫자가 맞는지 검증할 필요는 없다(그건 다른 일이다). 인용 여부만 적는다. 답변이 길면
근거 목록만 봐도 된다.

### 기록 규칙

- 회차 표는 이 파일 하단 "N19 기록" 절에 **위에서부터 최신순**으로 추가한다.
- 관측하지 못한 회차는 **건너뛴 것으로 적는다**. 빈칸을 "–"(없음)으로 메우면
  "그날 인용이 없었다"는 거짓 관측이 하나 생긴다. 기록하지 않은 것과 관측해서 없었던 것은 다르다.
- 인용이 생긴 회차에는 어떤 페이지가 인용됐는지 URL 을 같이 적는다. 그게 다음에 무엇을 더
  만들지 알려 준다.

## N24 — GSC 쿼리 갭 루틴 (월간, 매월 1일 10:00 KST)

### 왜 하는가

"노출은 있는데 클릭이 없는 질의"는 **검색엔진은 우리를 그 질문의 답으로 인정했는데, 사람은
우리 제목·설명을 보고 안 눌렀다**는 뜻이다. 순위를 올리는 것보다 훨씬 싸게 고칠 수 있는
문제이고, 무엇을 고쳐야 할지도 데이터가 직접 알려 준다. 측정→개선 루프의 본체다.

**선행 조건: 서치콘솔에 최소 4주치 데이터가 쌓여 있어야 한다.** 소유권 확인(2026-07-26)
직후라 데이터가 얇으면 이번 회차는 "데이터 부족"으로 적고 넘긴다 — 표본 20 노출짜리 질의로
제목을 고치면 노이즈를 쫓는 것이다.

### 절차

1. 서치콘솔 → 실적 → 검색결과 → 기간 **최근 28일** → "쿼리" 탭.
2. 표를 CSV 로 내려받는다(우상단 내보내기).
3. 다음 조건으로 거른다:
   - 노출 **100 이상**
   - CTR **1% 미만** (또는 클릭 0)
   - 평균 게재순위 **20위 이내** (순위가 낮아서 못 받는 클릭은 제목 문제가 아니다)
4. 남은 질의를 "페이지" 탭과 대조해 **어느 URL 이 그 질의로 노출되는지** 확인한다.
5. 질의별로 원인을 하나 고른다:
   - **제목·설명이 질문에 답하지 않는다** → 해당 페이지 `generateMetadata` 의 title/description 수정
   - **페이지에 그 질문의 답이 없다** → `QaBlock` 에 Q&A 항목 추가(실데이터로만)
   - **의도가 우리 페이지와 다르다** → 손대지 않는다. 억지로 맞추면 이탈률만 오른다.
6. 고친 내용을 커밋하고, 아래 기록표에 회차·질의 수·조치를 남긴다.
7. **다음 달 같은 질의의 CTR 을 확인한다** — 이 확인이 없으면 루프가 아니라 그냥 작업이다.

### 하지 말 것

- 클릭을 받기 위해 페이지에 없는 내용을 제목에 쓰는 것. 낚시 제목은 CTR 을 올리고 체류를 죽인다.
- Q&A 를 채우려고 수치를 지어내는 것. 답할 데이터가 없으면 그 질의는 넘긴다.
